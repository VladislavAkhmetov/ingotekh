# «Стеклянные пластины» v17

360 кадров с прозрачным фоном, одинаковой неподвижной камерой и грейдом v16.
Обе секвенции содержат `frame_0001.webp` … `frame_0360.webp`.
В `manifest.json` записаны фактическое качество и итоговый вес:

- `webp_1280`: 1280×1280, целевое качество 80, бюджет 18 000 000 байт.
- `webp_768`: 768×768, бюджет 8 000 000 байт.

Альфа каждого WebP проверена на точное совпадение с исходным изображением
соответствующего размера. Профиль sRGB встроен; фон в изображения не запечён.

## Просмотр

Открывать `preview.html` через локальный HTTP-сервер или сервер проекта,
а не по `file://`. Например, из этой папки выполнить `python -m http.server 8080`
и открыть `http://localhost:8080/preview.html`.

`scroll-sequence.js` — рабочий пример подключения: прогресс берётся прямо
из прокрутки, соседние кадры смешиваются в canvas, а CSS перемещает контейнер
справа налево. Для замены разметки используйте класс `FrostedScrollSequence`.

## Тайминг и раскладка

| Кадры | Движение внутри секвенции | Положение контейнера сайта |
| --- | --- | --- |
| 1–60 | Мягкое раскрытие пластин | Справа |
| 60–180 | Разворот к позе иллюстрации 2 | Переезд справа налево |
| 180–300 | Поворот вокруг локальной вертикали и превращение щита в сердце | Слева |
| 300–360 | Выравнивание сердца и едва заметное дыхание | Слева |

Позы 1, 180, 360 соответствуют согласованным ракурсам v16 / Figma 1, 2, 3.
Число кадров вращения — 120; деформация щита в сердце — 75 кадров.
Перемещение всей композиции по странице НЕ записано в изображения: оно задаётся
контейнеру. Так один комплект подходит для разных экранов.

Путь скролла: `clamp(900, 1200 * viewportWidth / 1440, 2100)` px.
Дробный номер кадра: `1 + clamp(progress, 0, 1) * 359`.
Это примерно 3,34 px прокрутки на кадр при ширине 1440 и до 5,85 px на больших
мониторах. Контейнер переезжает между кадрами 60 и 180 с плавными краями.

## Смешивание и память

Смешивать нужно взвешенные premultiplied RGBA двух кадров. Пример делает это
через `globalCompositeOperation = 'lighter'` на предварительно очищенном
прозрачном canvas. Обычный `source-over` для двух полупрозрачных кадров
уменьшает итоговую непрозрачность и даёт пульсацию.

Не декодируйте все 360 кадров в память: 1280²×4×360 — около 2,36 ГБ.
Пример хранит до 20 декодированных кадров, переиспользует сжатые Blob и
освобождает `ImageBitmap.close()` при вытеснении. Загружается один вариант
разрешения. При `prefers-reduced-motion` показывается статичный первый кадр.

## Рендер и проверки

- Исходный проект v16 и его рендеры сохранены отдельно.
- Cycles CUDA; минимум 512 фиксированных сэмплов, OIDN с albedo/normal.
- Seed неизменен между кадрами; выдержка 108°. Это пространственный денойзер
  с высоким числом сэмплов, а не заявление об использовании temporal denoiser.
- Проверка соседних медленно меняющихся кадров 179–181 находится в
  `quality-report.json`. При недостаточной стабильности очередь повышает
  число сэмплов до 1024, а при повторном провале останавливается для проверки.
- `geometry-report.json`: закрытые объёмы морфинга, отсутствие найденных
  пересечений с пластинами, проверка сохранности v16.
- Максимальное рассчитанное экранное смещение контрольных точек — около
  11,92 px при 1280. Общие поля камеры — около 5%; заполнение отдельных поз
  различается из-за ракурса. Динамическое кадрирование не применяется.
- Геометрия деформации запечена покадрово; короткий motion blur применяется
  к движениям объектов, форма внутри выдержки каждого кадра фиксирована.

Рекомендуемый фон блока: `#27292B`; прозрачные кадры можно размещать над
другим содержимым. Кадры не содержат встроенного цвета подложки.
